Post-mortems

Seven things that broke

A feature list says what I built. These say how I think when it goes wrong, which is the part of the job that actually costs money.

INC-01 · money path Resolved

A retried webhook paid an ambassador twice

Symptom
One referral payout landed in the ledger twice for a single customer payment.
Cause
Paystack retries a webhook when it doesn't get a timely response. My handler treated each delivery as a new event, so the second delivery re-ran the payout write.
Fix
Made the write conditional and idempotent — a $ne-filtered updateOne, so the payout can only be applied once regardless of how many times the event arrives.
Learned
Never pair that filter with upsert: true. The filter stops matching, and upsert obligingly inserts a second document, reintroducing the exact bug you just fixed.
INC-02 · performance Resolved

A slow dashboard that was never a slow query

Symptom
Seller quick-stats took roughly four seconds to load.
Cause
Profiling showed about 1ms of real database work sitting behind 111ms of round-trip latency — repeated 43 times. The queries were fine; the number of trips was not.
Fix
Collapsed 43 round trips into 3 with a single $group using conditional accumulators.
Learned
I measured $facet as the obvious alternative and it was slower: it re-scans the collection per branch. Warm up before timing anything, or you'll optimise the cold start instead of the query.
INC-03 · delivery Resolved

Three quarters of every storefront was wasted bytes

Symptom
Storefronts were slow on mobile data, which is how nearly every Nigerian buyer arrives.
Cause
Product images were being served straight from Cloudinary at original size, untransformed.
Fix
A transformation helper at the delivery layer took a real storefront from 1,852KB to 467KB — a 74% cut, with no visible quality loss.
Learned
Here it beat next/image, and the largest image above the fold must stay eager. Lazy-loading your LCP element makes the number worse while looking like an optimisation.
INC-04 · billing Resolved

Sellers on a free trial were charged four times the published rate

Symptom
One live seller was billed ₦4,120 in platform fees on a ₦103,000 order. At the rate published in our own terms it should have been ₦1,030.
Cause
A store inside its 14-day trial is stored as plan: 'free'. The fee lookup read that stored value, but free isn't a rate we publish, so it fell through to the wrong one. The trial's effective plan is growth_trial.
Fix
Every fee lookup now keys on getEffectivePlan(sub) and takes the subscription document, never a plan string. Trial, expired and free all alias onto the published Growth rate.
Learned
Derived state needs one resolver and no second readers. The invariant is now a unit test: a store inside its trial bills at 1%, and reading sub.plan directly is asserted against, because that is precisely what broke it.
INC-05 · silent failure Resolved

Renewing sellers were locked out with no warning email

Symptom
Sellers who renewed still hit a hard lock at the next expiry, having received none of the warning emails that are supposed to precede it.
Cause
Reminder and dunning emails de-duplicate against remindersSent and dunningsSent. Renewal extended the subscription but left both arrays populated, so every subsequent reminder looked already-sent and was skipped.
Fix
Every renewal path clears both arrays. Six files touch those flags, and missing any one leaves the bug alive on that path, so I fixed them together and backfilled the sellers already stuck in the broken state.
Learned
A de-duplication flag becomes a lie the moment the thing it guards resets. And patching forward isn't enough once bad state is in the database. The repair script matters as much as the fix.
INC-06 · blast radius Resolved

Rotating one secret took out most of the payment reminders

Symptom
Payment nudges to customers stopped going out after a routine credential rotation.
Cause
The cron endpoint is gated on CRON_SECRET. An external scheduler had been calling it every thirty minutes for months, and nothing in the repository recorded that it existed. Rotating the secret locked it out.
Fix
Restored the consumer with the new credential, and documented it where the next person will actually look — next to the endpoint it calls.
Learned
Grep only finds the callers you own. Before rotating any shared credential I now inventory who authenticates with it, including things configured once in a browser years ago and never written down.
INC-07 · shortlist Resolved

A job board that answers 200 for a job that is gone

Symptom
Links in my morning digest opened on an empty page. The tool was recommending roles that no longer existed.
Cause
Ashby serves its board shell with HTTP 200 for a posting it cannot resolve. One company runs the posting API but leaves its hosted board dark, so the API hands out URLs that render nothing. No status code ever says so.
Fix
A verification stage that opens each shortlisted link and asks whether the page still names that job, reading the bootstrap payload, the title and the role's own words. It fails open: a timeout or a 429 marks nothing dead, so a flaky connection cannot silently empty the digest.
Learned
My first checker searched the HTML for 404 and declared six live jobs dead. The string was inside SVG path data (13.3404). A test now carries those exact coordinates.
